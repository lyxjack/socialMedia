# /research — 小红书内容研究与发布工作流

## 概述

端到端工作流：热点调研 → 素材准备 → 5 路并行文案生成 → 评分对比 → 发布。

## 输入

- `$ARGUMENTS`: 用户描述的内容需求（如"春季穿搭分享"、"咖啡探店"）

---

## Phase 1: 热点调研

### 1.1 服务启动检查

```
1. 检查端口 18060: lsof -i :18060
2. 如未启动:
   cd xiaohongshu-mcp && go run . -token "$XHS_API_TOKEN" &
   等待 2 秒 → curl -s http://127.0.0.1:18060/health
3. 检查登录状态: 调用 MCP 工具 check_login_status
4. 如未登录: 调用 get_login_qrcode → 展示二维码 → 等待用户扫码
```

### 1.2 关键词搜索

根据用户需求 `$ARGUMENTS`，提取 2-3 个核心关键词，执行多轮搜索:

```
对每个关键词:
1. 调用 search_feeds(keyword=关键词, sort_by="最多点赞")
2. 调用 search_feeds(keyword=关键词, sort_by="最新")
3. 从结果中选取互动量 Top 5 的笔记
4. 对 Top 5 笔记调用 get_feed_detail 获取完整内容和评论
```

### 1.2.1 视觉数据采集

从搜索结果和笔记详情中提取图片数据，并下载图片进行视觉分析:

**Step A — 结构化数据采集**

```
对互动量 Top 5 的图文笔记 (type=normal)，调用 get_feed_detail 获取:
1. 图片总数 (imageList.length)
2. 每张图的尺寸 (width/height)
3. 正文内容 (desc)
4. 每张图的 URL (urlDefault)
```

**Step B — 下载 Top 3 笔记的全部图片进行视觉分析**

```
从 Top 5 中选取互动量最高的 3 篇图文笔记:
1. 为每篇笔记创建临时目录: .in-process/scratch/visual-ref/<feed_id>/
2. 下载该笔记 imageList 中的所有图片 (通过 curl 或 WebFetch 下载 urlDefault)
3. 用 Read 工具逐张查看图片，记录:
   - 封面图(第1张): 主体是什么 (人物/风景/产品/第一视角)、构图方式、色调
   - 后续每张图: 内容类型、在叙事中的角色 (背景交代/种草核心/细节/收尾)
4. 分析 3 篇笔记的图片排列共性，提取排版模式
5. 分析完成后删除临时图片目录
```

**Step C — 汇总视觉分析结论**

```
基于 Step A 的结构化数据 + Step B 的视觉分析，汇总:
- cover_ratio: 封面图比例分布 (如 "3:4 占 70%, 1:1 占 20%")
- image_count: 图片数量分布 (如 "6-9 张居多")
- cover_type: 封面图内容类型分布 — 基于实际看到的图片内容，不是推断
- image_sequence_pattern: 图片排列模式 — 基于实际看到的多篇笔记图片顺序提取共性
- visual_style: 色调/滤镜/构图的共性特征
```

注意:
- 只下载 Top 3 篇的图片（控制耗时），其余用结构化数据分析
- 下载的图片仅用于分析，分析完成后立即删除
- 如果 get_feed_detail 返回空数据，fallback 为下载搜索结果中的封面图 (cover.urlDefault) 进行分析

### 1.3 提取爆点摘要

**强制输出规则**: 无论用户在 `/research` 后提出什么需求，Phase 1 的调研摘要必须**完整输出以下所有板块**。用户只会描述"要发什么内容"，不会每次告诉你需要产出哪些分析维度。以下板块缺一不可:

从抓取结果中提炼:

```markdown
## 调研摘要

### 热门关键词
- [关键词1] — 出现频次，典型用法
- [关键词2] — ...

### 爆款标题模式
- [标题1] — 点赞数，标题结构分析（拆解句式结构，如"开飞机去XX是什么体验"）
- [标题2] — ...
- 可直接套用的标题模板: [从爆款中抽象出 2-3 个填空式模板]

### 高频标签
- 核心标签 (必选): #标签1 #标签2 ...
- 流量标签 (可选加): #标签3 #标签4 ...
- 按使用场景分组 (如: 主题类/地域类/情绪类/实用类)

### 内容风格趋势
- 文案风格（口语化/专业/种草/测评）
- 图片风格（实拍/精修/拼图/对比图）
- 互动引导模式（提问/投票/分享经历）
- 爆款共性总结: [Top 笔记的共同特征是什么]

### 评论区热词
- 用户最关心的问题
- 高频提问
- 情绪关键词（羡慕/好奇/质疑）
- **文案应主动回应的点**: [列出 2-3 个评论区高频问题，建议在正文中提前回答]

### 视觉排版分析
基于 1.2.1 采集的视觉数据，输出以下结论:

#### 封面图策略
- 爆款封面图类型: [如"驾驶舱第一视角"/"人+场景合影"/"航拍俯视"]
- 推荐封面比例: [如"3:4 竖图"]
- 封面要素: [如"需要有人物出镜"/"需要有强视觉冲击的场景"]

#### 图片数量与排序建议
- 推荐图片数量: [基于 Top 笔记的图片数量分布]
- 推荐排列顺序: [基于 Top 笔记的图片序列模式，如:]
  1. 封面: [最抓眼球的类型]
  2. 第 2-3 张: [场景/背景交代]
  3. 中间张: [核心内容/高潮]
  4. 最后 1-2 张: [收尾/互动引导]
- 排列逻辑: [故事线/时间线/情绪递进/对比]

#### 图片风格要求
- 比例: [统一比例还是混搭]
- 色调: [暖色/冷色/自然]
- 构图: [常见构图模式]
```

**再次强调**: 以上所有板块（热门关键词、爆款标题模式、高频标签、内容风格趋势、评论区热词、视觉排版分析）每次执行都必须完整输出，不可省略。

将调研摘要保存到 `.in-process/scratch/research-brief.md`。

## Phase 2: 素材准备

### 2.1 创建素材文件夹

根据 `$ARGUMENTS` 生成一个简短的文件夹名称:

```bash
mkdir -p source/<需求名称>/images
mkdir -p source/<需求名称>/videos
```

### 2.2 暂停等待用户

根据 Phase 1.3 的「视觉排版分析」结论，生成针对本次内容的选图和排版建议，与素材文件夹信息一起展示给用户。

向用户展示:

```
素材文件夹已创建: source/<需求名称>/

## 选图与排版建议

根据对 {N} 篇同类爆款笔记的分析:

**封面图**: {Phase 1.3 得出的封面策略，如"建议选一张驾驶舱第一视角的照片，竖图3:4"}
**推荐张数**: {如"6-9张"}
**建议排列顺序**:
  1. {封面建议，如"驾驶舱视角 / 人+飞机合影 — 停住滚动"}
  2. {如"起飞前的准备 / Palo Alto机场全景 — 交代背景"}
  3. {如"飞行途中的窗外风景 / 航拍 — 展开旅程"}
  4. {如"目的地标志性景点 — 高潮"}
  5. {如"细节/趣味瞬间 — 丰富故事"}
  6. {如"落地/返程 / 全程路线图 — 收尾"}

**注意**: 以上建议基于数据分析，你可以按自己的素材灵活调整。

---

请将素材放入:
- 图片 → source/<需求名称>/images/  (jpg/png/webp/heic, 至少1张)
- 视频 → source/<需求名称>/videos/  (mp4/mov, 可选)
- 补充说明 → source/<需求名称>/brief.md (可选)

注意: 图片和视频二选一。如果同时存在，优先使用视频。

素材放好后请回复"ok"或"继续"。
```

**重要**: 上面的排版建议内容不是固定模板，必须根据 Phase 1 的实际调研结论动态生成。不同主题的建议会完全不同。

**等待用户确认后才继续。**

### 2.3 素材扫描

用户确认后:

```
1. 扫描 source/<需求名称>/images/ 和 videos/
2. 确定发布类型: 有视频 → 视频笔记 / 仅图片 → 图文笔记
3. 读取 brief.md（如存在）
4. 将素材信息整理为:
   - media_type: "image" | "video"
   - media_paths: [绝对路径列表]
   - brief: brief.md 内容或"无"
```

### 2.4 素材视觉分析与排序建议

仅图文笔记且图片 >= 2 张时执行此步骤:

```
1. 用 Read 工具逐张查看用户放入的所有图片
2. 对每张图片记录:
   - 文件名
   - 内容描述 (人物/风景/产品/细节/文字信息等)
   - 视觉特征 (色调/构图/冲击力强弱)
3. 对照 Phase 1.3「视觉排版分析」中的排版建议，将用户图片匹配到推荐位置:
   - 哪张最适合做封面 (匹配封面策略)
   - 哪些图承担叙事中段 (场景/种草/高潮)
   - 哪张适合收尾 (实用信息/互动引导)
4. 生成推荐排列顺序，展示给用户:
```

```markdown
## 素材分析与排序建议

我看了你放入的 {N} 张图片，结合调研中 Top 笔记的排版模式，建议如下排列:

| 推荐顺序 | 文件名 | 图片内容 | 排在这里的原因 |
|---------|--------|---------|--------------|
| 1 (封面) | {文件名} | {内容描述} | {如"驾驶舱第一视角，冲击力最强，与爆款封面模式一致"} |
| 2 | {文件名} | {内容描述} | {如"Palo Alto 机场全景，交代出发背景"} |
| 3 | {文件名} | {内容描述} | {如"飞行途中航拍，展开旅程"} |
| ... | ... | ... | ... |

如果你同意这个顺序，回复"ok"；
如果想调整，告诉我你想怎么改。
```

**等待用户确认排列顺序后才进入 Phase 3。**

确认后将 media_paths 按用户认可的顺序排列，后续 Phase 3-5 均使用此顺序。

## Phase 4: 评分排序与用户选择

### 4.1 评分维度

收集 5 个 agent 的输出后，按以下维度评分（1-10 分）:

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| **平台适配度** | 30% | 标题≤20字、口语化程度、emoji/标签使用、符合小红书调性 |
| **Hook 强度** | 25% | 首行/标题能否停住滚动（好奇缺口/数据冲击/个人故事/争议性） |
| **关键词覆盖** | 20% | 是否包含 Phase 1 抓取的热门关键词/标签/评论区热词 |
| **素材匹配度** | 15% | 文案与图片/视频内容的关联性，描述是否准确呼应素材 |
| **CTA 明确度** | 10% | 是否有清晰互动引导（评论/收藏/关注/分享经历） |

### 4.2 展示格式

```markdown
## 文案对比评审

### 评分排名

| 排名 | 来源 | 综合分 | 适配度 | Hook | 关键词 | 素材匹配 | CTA |
|------|------|--------|--------|------|--------|---------|-----|
| 1 | Agent X | 8.5 | 9 | 8 | 9 | 8 | 7 |
| 2 | Agent Y | 8.2 | 8 | 9 | 7 | 9 | 8 |
| ... | ... | ... | ... | ... | ... | ... | ... |

### 推荐理由
- **第 1 名 (Agent X)**: [1-2 句话说明为什么排第一]
- **第 2 名 (Agent Y)**: [亮点和不足]

---

### 文案 #1 (推荐) — 来源: Agent X
> 标题: ...
> 标签: ...
>
> 正文...

---

### 文案 #2 — 来源: Agent Y
> ...

（以此类推展示全部 5 篇）

---

请选择你想发布的文案编号 (1-5)，或输入"修改 N"对第 N 篇提出修改意见。
```

### 4.3 等待用户选择

- 用户输入编号 → 进入 Phase 5
- 用户输入"修改 N" → 按用户意见修改对应文案 → 重新展示
- 用户输入"重新生成" → 回到 Phase 3

## Phase 5: 发布

将最终要发布的所有内容完整、清晰地展示给用户。**不可省略任何部分，不可截断正文。** 用户必须在看到全部内容后才能做出发布决定。

```markdown
---
## 即将发布的完整内容
---

### 标题
{选定文案的完整标题}

### 正文
{选定文案的完整正文 — 必须展示全文，不可用"前100字..."截断}

### 标签
{按发布顺序列出所有标签，如: #开飞机 #私人飞机 #黄石公园 #大提顿 #飞行体验}

### 图片排列顺序
（图文笔记时展示）

| 顺序 | 文件名 | 用途说明 |
|------|--------|---------|
| 1 (封面) | {文件名} | {为什么选这张做封面} |
| 2 | {文件名} | {这张图在叙事中的作用} |
| 3 | {文件名} | ... |
| ... | ... | ... |

### 视频
（视频笔记时展示）
- 文件: {文件名}
- 时长: {如可获取}

---
以上是将要发布到小红书的全部内容，请确认:
- 标题、正文、标签是否需要修改？
- 图片顺序是否需要调整？
- 确认无误请回复"发布"，需要修改请说明。
```

**关键规则**:
- 正文必须完整展示，不可截断
- 图片必须列出排列顺序和每张图的用途说明
- 标签必须列出完整列表
- 用户只有回复"发布"或明确表示同意后，才可进入 5.3 执行发布
- 用户提出任何修改意见 → 修改后重新展示完整预览 → 再次等待确认

### 5.2 检查登录状态

用户确认发布后，调用 `check_login_status`，如已过期则重新引导登录。

### 5.3 执行发布

**图文笔记:**
```
调用 MCP 工具 publish_content:
- title: 选定标题
- content: 选定正文（含标签）
- images: [按 5.1 中确认的顺序排列的素材绝对路径列表]
- tags: [标签列表]
```

**视频笔记:**
```
调用 MCP 工具 publish_with_video:
- title: 选定标题
```
