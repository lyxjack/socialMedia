# Project Guidelines

## 启动流程

当用户要求启动服务时，执行以下步骤：

1. 检查 18060 端口是否已被占用：`lsof -i :18060`
2. 如已占用，跳过启动，提示服务已在运行
3. 如未占用，后台启动服务：`go run . -token "$XHS_API_TOKEN"` （如未设置环境变量则不带 token）
4. 等待 2 秒后验证：`curl -s http://127.0.0.1:18060/health`
5. 确认 MCP 已注册：`claude mcp list` 中应有 `xiaohongshu-mcp`
6. 启动完成后，向用户展示可用操作提示，例如：
   - 搜索笔记、用户
   - 获取笔记详情、评论
   - 下载图片/视频
   - 查看/管理 cookies
   - 其他已注册的 MCP 工具能力

##  本地开发规范

- 要求每次修改完后,需要帮我格式化 Go 源码文件.
- 测试过程中产生的脚本和build中间文件,如果没有必要,则删除.
- 所有的feature变更,都需要使用分支进行开发.
- 在我未同意之前, 你不能推送到远程.
- 我需要: 1.本地 review; 2.远程 PR review.
- 不要过度设计, 保持代码的简洁和易读.
- 使用中文注释，一定要简洁明了.专业名词可以用英文.

## PR Review 重点

- 重点：PR 代码中如果出现大量的 JS 注入的行为，要检查一下是否是必须的，如果可以用 Go 的 go-rod 替代的话，则直接评论需要用 go-rod 行为替代。
